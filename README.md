# IRODORI-VOICE

Irodori-TTS を、VOICEVOX のエディタからそのまま使えるようにする音声合成エンジンです。AivisSpeech や COEIROINK と同じ構成——VOICEVOX ENGINE 互換の API を持つ常駐エンジンと、VOICEVOX エディタの組み合わせ——で動きます。

## 構成の考え方

```text
┌─────────────────────────┐        ┌──────────────────────────────┐
│  VOICEVOX エディタ       │  HTTP  │  IRODORI-VOICE エンジン       │
│  （Electron + Vue）      │───────▶│  （Python + FastAPI）         │
│  慣れた操作・辞書・台本   │ :50121 │  Irodori-TTS                 │
└─────────────────────────┘        └──────────────────────────────┘
         ▲                                      ▲
         │ 同じ API を叩く                        │
  ゆっくりMovieMaker / AviUtl プラグイン など
```

エディタを自作せず VOICEVOX のものを使うため、**操作を覚え直す必要がありません**。エディタ側の改変も、VOICEVOX の公開リポジトリをそのまま触る形になります。

## 使いはじめるまで

このリポジトリはソースだけを公開しています。**手元でビルドして使う形**です。実行ファイルを同梱していないのは、GPU 版が 5GB を超えて配布しづらいことと、VOICEVOX エディタ（LGPL-3.0）の改変物を同梱しない形を保つためです。

必要なものと、かかる時間の目安です。

| | 必要なもの | 時間 |
| --- | --- | --- |
| 1. エンジンの依存 | Python 3.10 以上 | 10 分ほど |
| 2. エディタの用意 | Node.js 24 系（pnpm は自動で入ります）、git | 10〜20 分 |
| 3. 起動 | — | すぐ |
| （任意）実行ファイル化 | 上記に加えてディスク 20GB | 50 分以上 |

3 まで済ませれば、`start-voicevox-editor.bat` で使いはじめられます。実行ファイルへ固めるのは、他の PC へ配ったり Python 環境なしで動かしたい場合だけで構いません。

初回の起動時に、音声合成モデル（約 3GB）を Hugging Face から取得します。取得後はオフラインで動きます。

## 機能ハイライト

- 🔌 **VOICEVOX ENGINE 互換 API** — `/audio_query` `/synthesis` `/speakers` ほか 30 のエンドポイントを本家と同じ形で提供します。VOICEVOX エディタ、ゆっくりMovieMaker、AviUtl プラグインから区別なく使えます。
- 📖 **ユーザー辞書が「完全に」効きます** — エディタの仕様で強制的に全角保存される英数字も、内部のNFKC正規化により大文字小文字・半角全角（カンマ等含む）を区別せず本文とマッチさせます。当てる位置は形態素解析で求めた語の切れ目に限るため、登録語が別の語の途中へ紛れ込むこと（「ＧＵＩ」の登録が「ログイン」に、「1,000」の登録が「21,000」に当たる類）はありません。語の一部にも当てたい場合は、その語の優先度を上げてください。優先度を最大にした語は単独の語として切り出され、より長い語の中でも当たるようになります。ただし、形態素解析が 1 語として扱う複合語（「証券取引所」「東京証券取引所」など）の内側にある語は、優先度を上げても切り出せないことがあります。その場合は複合語そのものを登録するか、フレーズ分割辞書で区切ってください。辞書更新時にはエンジンのキャッシュが即時クリアされるため、即座に新しい読みが音声と画面下のカタカナ（アクセント句表示）の両方へ反映されます。
- 🔣 **飾りの記号は読み上げません** — 本文に置かれた「※」「：」「・」「☆」「♪」のような読みを持たない記号は、モデルへ渡す前に落とします。落とすかどうかは形態素解析の結果で決めるため、「50%」の「%」や「25℃」のように読みを持つ記号はそのまま残ります。読ませたい記号は辞書へ登録してください。登録した記号は読みへ置き換わってから渡ります。なお句読点・三点リーダ・括弧・引用符と、モデルへの指示になる注釈絵文字は、間や語り分けの材料になるため残します。
- 🎭 **注釈を補助指示でも反映** — 感情・話し方・状態・音や効果の絵文字に対応するキャプションを自動で加えます。本文には指示文を混ぜず、読み上げとは別の条件として渡します。標準モデル向けの機能です。
- 🗣️ **漢字の読みを生成へ反映** — Irodoriへ渡す前に、解析できた漢字語をひらがなの読みに置き換えます。エディタには元の文章を残し、辞書で指定した読みを優先します。絵文字・句読点・仮名表記は保持します。
- 📝 **フレーズ分割辞書** — 長い複合語がひと塊のまま読まれて崩れる場合に、「東京特許許可局=東京_特許許可局」のように登録しておくと、外部ツールから届いたテキストへエンジンが自動で当てます。読点（、）で区切ればそこで間が空き、空白またはアンダースコアで区切れば、間を空けずにアクセント句だけが分かれます。ここで区切った位置は、読み方＆アクセント辞書の当たり方にも効きます。「証券取引所」のように解析が 1 語として切る複合語では、その内側へ登録した「取引所」は当たりませんが、`台湾証券取引所=台湾証券_取引所` と区切っておくと当たるようになります。登録はエディタのメニュー「設定 → フレーズ分割辞書」から行えます。辞書はユーザー領域（Windows では `%APPDATA%\IRODORI-VOICE\word_splits.txt`）に置かれ、テキストエディタで直接開いて書き足すこともできます。
- ⚡ **ハイブリッド倍速（高品質タイムストレッチ）機能** — エディタで話速を変更した際、AIには一番安定する「1.0倍速」に完全固定して生成させ、背後でプロ用DSP（ボーカル特化チューニング済みのフェーズボコーダー）がピッチを保ったまま指定速度へ伸縮させます。これにより、拡散モデル特有の早口指定時の幻覚暴走（宇宙語・言語障害化）を完全に防ぎ、高音質のまま全速度域に対応できます。
- 🧠 **シード値生成時の安定化パッチ** — 参照音声なし（シード値）で架空の話者を生成する際、AIのテキストへの忠実度（cfg_scale_text）を内部で強制ブーストし、辞書の読み飛ばしや発音のブレを強力に抑え込みます。
- 🎛 **できないことは `engine_manifest` で申告** — モーラ単位の音高・長さ調整には対応しないため、エディタ側がそのコントロールを自動で無効化します。効かないつまみを触らせません。
- ✂️ **長文を自動で区切ります** — 句読点を見て 1 区間 30〜40 文字へ割り、同じ声のまま繋ぎ直します。Irodori-TTS の 30 秒制限で末尾が切れることがなくなり、待ち時間も短くなります。
- 🔊 **薄くなった声を自動で補正** — 「あっ、あん、ッ、あ～…っ！」のように感嘆詞だけが並ぶ行は、モデルが息声として読み上げるため、声の土台になる低域が普通の文の約 0.3 倍まで落ち、AM ラジオのように薄く聞こえます。合成後に不足分だけを持ち上げます。足りている行には掛かりません。
- ⚡ **MeanFlow 版で実時間より速く** — 少ステップ生成向けに蒸留された版へ 1 コマンドで切り替えられます。実測で 79 文字が 9.4 秒（実時間比 0.64x）です。ただしこの版は推論時の条件付けスケールを無効化するため、**キャプションによる喋り分けと、参照音声への寄せ具合が効かなくなります**。表現を優先する場合は標準版をお使いください（既定は標準版です）。
- 🔁 **待ち時間を削る四段構え** — 長文の分割、合成結果のキャッシュ（同じ要求は即時）、次の行の先読み、参照音声の latent キャッシュ。
- 🎙 **シードの声を焼き付けて固定** — シード値から話者を作れるため、**音声モデルを 1 つも持っていなくても話者を増やせます**。作成時にその声を 1 本だけ合成し、参照音声として保存するので、行をまたいでも同じ声で鳴ります。既にある話者も、管理画面の「声を固定する」であとから固定できます。
- 🎭 **シード話者の表現を優先** — 新しくシードから作った話者と「声を固定する」で固定した話者は、保存後の読み上げに40回生成・表現CFG 5・参照CFG 2を使います。生成時間は長くなりますが、声のお手本を保ちながら感情の指示を強めます。表現の出来は文章と話者によって異なります。
- 🗣 **参照音声から話者を作成** — 手持ちの音声を数本渡すと、その声に寄せた話者を登録できます。Speaker Inversion の話者埋め込みも取り込めます。
- 🪄 **手本の声から、Irodori-TTS の抑揚で** — 取り込んだ音声モデルの声を手本にして、Irodori-TTS の話者を作れます。声はモデルから、抑揚と間の取り方は Irodori-TTS から受け継ぎます。あわせて 25 種類のスタイル（注釈絵文字つき）も作られるため、同じ声のままゆっくり喋らせたり、囁かせたり、叫ばせたりできます。
- 📦 **音声モデルを 1 ファイルにまとめられます** — 学習済みモデル（.safetensors）・ONNX モデル（.onnx）・ハイパーパラメータ（config.json）・スタイルベクトル（style_vectors.npy）を `.irvm` へ束ねます。以後はこの 1 ファイルを渡すだけで取り込めるため、「どれか 1 つ足りない」が起きません。
- 🖼 **話者にアイコンを付けられます** — 管理画面の話者一覧で、枠をクリックするか画像をドロップするだけで設定できます。付けたアイコンはエディタの話者一覧と立ち絵にそのまま出ます。取り込んだモデルが画像を同梱している場合は、それを自動で使います。
- 🎨 **管理画面を同梱** — エンジンが `http://127.0.0.1:50121/admin` で管理画面を配信します。音声モデルの追加、話者の作成、合成モデルの切り替えをブラウザから行えます。読み上げの操作は VOICEVOX エディタ、素材の準備はこの画面、と役割を分けています。
- 🔒 **オフライン動作** — エンジンは 127.0.0.1 のみで待ち受け、外部へ通信しません。
- 🧱 **実行ファイルにまとめられます** — `コンパイル.bat` ひとつで、Python 環境なしに動く形へ固められます。インストーラ・単一実行ファイル・フォルダの 3 形式が出て、どれもエンジンを同梱しているため、起動すれば合成まで通ります。**CPU 版と GPU 版を作り分けられる**ので、GPU の有無を問わず配れます。

## セットアップ

### 1. エンジンの依存をそろえる

Python 3.10 以上が必要です。同梱の `requirements.txt` で一式そろいます。

```bash
python -m venv runtime
runtime\Scripts\python -m pip install -r requirements.txt
```

**`runtime` という名前で作ってください。** 各バッチはこの順に Python を探します。

1. `runtime\Scripts\python.exe`
2. `..\Irodori-TTS\.venv\Scripts\python.exe`（隣に Irodori-TTS を置いている場合）
3. PATH の `python`

GPU で動かす場合は、先に CUDA 版の `torch` を入れてから `requirements.txt` を適用してください。手順は `requirements.txt` の冒頭に書いてあります。導入されている `torch` が CPU 版であれば、GPU があっても使用しません。

**CUDA は 12.6 を選んでください。** 12.8 以降のビルドは Maxwell / Pascal / Volta のサポートを削除しており、GTX 10xx 世代では動きません。12.6 は Maxwell から Hopper（GTX 750Ti 〜 RTX 40xx）までを覆う最後の世代です。RTX 50xx（Blackwell）をお使いの場合は 12.8 以降が必要です。

VRAM の量で配置が変わります。6GB 以上あればモデル本体も GPU へ載せ、足りない場合はモデルを CPU に置いてコーデックだけ GPU に残します。**足りない GPU へ手動でモデルを載せると、かえって大幅に遅くなります**（不足分をシステムメモリへ退避しながら動くため）。設定は `auto` のままをおすすめします。

エンジンはエディタが子プロセスとして起動するため、ここで起動する必要はありません（「3. 起動する」を参照）。動作だけを確かめたい場合は `start-engine.bat` を実行し、`http://127.0.0.1:50121/speakers` が話者一覧を返せば動いています。

日本語の読みには `pyopenjtalk-plus` を使います（`requirements.txt` に含まれています）。Windows では本家の `pyopenjtalk` が Visual Studio のビルド環境を要求するため、ビルド済み wheel のあるこちらを使っています。未導入のまま動かすこともできますが、読みはカタカナ部分のみの簡易処理になります。

`requirements.txt` の末尾にある 2 つは任意の追加依存です。入れなくても Irodori-TTS の合成は動きます。なお `style-bert-vits2` は AGPL-3.0 で、入れると BERT を初回に取得します（約 1.3GB）。また、その依存の `pyopenjtalk-dict` が `pyopenjtalk` を上書きして読みの解析が壊れることがあります。その場合は次で戻します。

```bash
pip uninstall pyopenjtalk-dict
pip install --force-reinstall pyopenjtalk-plus
```

### 2. VOICEVOX エディタを用意する

```bash
setup-voicevox-editor.bat
```

このバッチが行うことは次の 6 つです。

1. VOICEVOX 公式リポジトリ（LGPL-3.0 / 一部 MIT）を `editor-voicevox/` へ取得する
2. IRODORI-VOICE エンジンへ接続する `.env` を配置する
3. `package.json` の `name` を `irodori-voice` へ変更する（`package.json` への変更はこの 1 行のみ）
4. `tools/patch-editor.mjs` で IRODORI-VOICE 用の改変を当てる
5. `pnpm install` で依存を導入する
6. `pnpm run license:generate` でヘルプのライセンス情報を生成する

Node.js 24 系が必要です。VOICEVOX は pnpm を使うため、PATH に pnpm が無い場合は
バッチが corepack または npm から導入します。

#### VOICEVOX エディタへの改変点

次の 11 箇所です。いずれも `tools/` のスクリプトが当てるため、`editor-voicevox/` で
`git pull` したあとに同じスクリプトを流し直せば、上流の更新を取り込めます。改変物を
同梱して配布する形ではないので、LGPL-3.0 のソース提供義務も発生しません。

**1. `package.json` の `name`**（`tools/brand-editor.mjs`）

`voicevox` から `irodori-voice` へ変えます。VOICEVOX の `vite.config.ts` が
`package.json` の `name` と `VITE_APP_NAME` の一致を検証するためです。併せて Electron の
ユーザーデータ保存先も分かれるので、既に導入済みの VOICEVOX の設定を壊さずに共存できます。

**2. 長文警告の閾値**（`tools/patch-editor.mjs`）

エディタは 80 文字を超えた行へ「文章が長いと正常に動作しない可能性があります」と表示します。
これは本家エンジンが長いテキストで不安定になることを前提にした注意書きで、IRODORI-VOICE には
当てはまりません。こちらのエンジンは受け取った文を内部で区間へ割ってから合成し、1 本の音声として
返します（実測では 108 文字の行が 4 区間へ割られ、問題なく合成できています）。

そこで閾値を 300 文字へ引き上げます。警告そのものは残します。合成時間は長さに比例して伸びるため、
極端に長い行には注意が要るという点は本家と変わりません。

**3. 「音声モデルの管理」画面の組み込み**（`tools/patch-editor.mjs`）

音声モデルの取り込みと作成、話者の作成を行う画面をエンジンが配信しています。これをエディタ内の
ダイアログとして開けるようにし、メニューの「エンジン」へ入口を増やします。別のブラウザや別のバッチへ
動線が分かれないよう、エディタの中で完結させています。

追加するファイルは `tools/editor-patch/`（`AdminDialog.vue` と `adminDialogState.ts`）にあり、
パッチ適用時にコピーされます。画面の中身はエンジンが配信するものを枠内へ読み込むだけなので、
機能を足すときにエディタ側へ手を入れる必要はありません。

**4. 貼り付けたテキストの分割**（`tools/patch-editor.mjs`）

エディタは貼り付けたテキストの `。` すべての後ろへ改行を入れてから行へ割ります。これでは
鉤括弧で囲まれたセリフが途中で切れ、切れた断片だけを合成すると音がこもります（後述の
「貼り付けたテキストの分割」を参照してください）。

そこで、鉤括弧（`「」`・`『』`）の中の `。` では割らないようにします。分割処理は
`tools/editor-patch/irodoriTextSplit.ts` にあり、単体テストも一緒にコピーされます。
閉じ括弧が無いまま終わる開き括弧は、囲みとして扱いません。会話の書き出しだけを貼ったときに、
テキスト全体が 1 行へ固まらないようにするためです。

**5. 既定テーマ**（`tools/patch-editor.mjs`）

既定のテーマを「墨（くらい）」にします。テーマを足しただけでは選ばれないため、設定の初期値
そのものを差し替えています。一度でも起動した環境では保存済みの設定が優先されるため、その場合は
設定 → テーマから選び直してください。

**6. 歌唱に対応した話者がいない場合のソングエディタ**（`tools/patch-editor.mjs`）

このエンジンは歌唱合成に対応せず、`/singers` は空の一覧を返します。本家のソングエディタは
歌手が 1 人もいない状態を想定しておらず、既定の歌手を決める箇所で一覧の先頭を無条件に読むため、
`Cannot read properties of undefined (reading 'metas')` で失敗します。しかもこれを呼ぶのは
新規プロジェクトの作成で、トーク側しか使っていなくても巻き添えになります。

そこで、歌手が見つからない場合は歌手を設定せずに抜けるようにし、併せてタイトルバーのソング
切り替えボタンを出さないようにします。前回ソングを開いたまま終了していた環境では、起動時に
トークへ戻します。歌唱に対応した話者を持つエンジンを追加すれば、切り替えボタンは自動的に戻ります。

**7. 更新確認の失敗の扱い**（`tools/patch-editor.mjs`）

エディタは起動時に新しいバージョンが出ていないかを確認します。IRODORI-VOICE では外部サイトへ
問い合わせないよう、`.env` の `VITE_LATEST_UPDATE_INFOS_URL` でその取得先をエンジン自身の
`update_infos.json`（常に空の一覧を返します）へ向けています。

ところがこの確認は、エンジンが起動しきる前に走ります。エンジンの起動には十数秒かかるため、
確認は必ず失敗します。本家の `useFetchNewUpdateInfos` は取得処理を catch の無い即時実行関数へ
投げっぱなしにしており、しかもヘルプ画面と更新通知の 2 か所から呼ばれるため、**起動のたびに
ログへ「Failed to fetch」が 2 件記録されていました**。

そこで、取得に失敗した場合は更新なしとして扱い、警告としてログへ残すようにします。取得先が
常に空の一覧を返す以上、この確認が成功しても結果は変わらないため、動作への影響はありません。

**8. ヘルプの文面**（`tools/patch-editor.mjs`）

`public/` に置かれた利用規約・プライバシーポリシー・使い方・よくあるご質問・お問い合わせ・
開発コミュニティは VOICEVOX のもので、そのままではヘルプに VOICEVOX の内容が並びます。
利用規約とプライバシーポリシーに至っては、本家リポジトリでは中身が「ダミー利用規約」です
（本家の配布物では CI が本物へ差し替えています）。

そこで、IRODORI-VOICE 向けに書いたものへ入れ替えます。文面は `tools/editor-patch/help/` に
あります。この 7 ファイルだけは置換ではなく丸ごとの差し替えになるため、初回に
`<ファイル名>.orig` として本家の中身を残し、`--revert` で書き戻します。

ヘルプの「ライセンス情報」に並ぶ `public/licenses.json` も本家ではダミーです。こちらは
差し替えではなく、セットアップ時に `pnpm run license:generate` で実際の依存から生成します。

**9. 話者を追加したときの並び替え画面**（`tools/patch-editor.mjs`）

本家は、並び順に登録されていない話者を見つけると「キャラクター並び替え・試聴」を全画面で開きます。キャラクターが増えるのが年に数回という前提の作りですが、IRODORI-VOICE では管理画面から話者をいくつでも作れるため、作るたびにこの画面が開いて手が止まります。

そこで自動で開くのをやめます。並び替えは「設定」→「キャラクター並び替え・試聴」からいつでも開けるため、機能は失われません。

**10. ｲﾝﾄﾈｰｼｮﾝ欄・長さ欄のタブ**（`tools/patch-editor.mjs`）

アクセント欄の左には「ｱｸｾﾝﾄ」「ｲﾝﾄﾈｰｼｮﾝ」「長さ」の 3 つのタブが並びます。後ろの 2 つはモーラ単位で音の高さと長さを詰める欄で、読み上げを作るだけなら使いません。

そこでタブを「ｱｸｾﾝﾄ」だけにします。併せて、この 2 つの欄へ移る `2` / `3` キーのホットキー登録も外します。タブだけを消すと、キーを押したときに表に出ていない欄の中身へ切り替わってしまうためです。

設定の「キーボードショートカット」には「ｲﾝﾄﾈｰｼｮﾝ欄を表示」「長さ欄を表示」の行が残ります。この項目名は設定ファイルの検証にも使われており、一覧から消すと、その名前を保存済みの設定ファイルが読み込めなくなるためです。押しても何も起きない行として残しています。

**11. 読み方＆アクセント辞書の書き出しと取り込み**（`tools/patch-editor.mjs`）

本家の辞書画面には書き出しも取り込みもなく、登録した語はそのエンジンの中だけに溜まっていきます。辞書画面のヘッダーへ「書き出し」と「取り込み」を足し、ファイルで持ち運べるようにします。

ファイルの形は AivisSpeech が書き出すものに合わせています。AivisSpeech で作った辞書をそのまま読み込めますし、こちらから出したファイルを AivisSpeech でも読めます。形を合わせる仕事はエンジンが受け持ち（`/user_dict/aivis`）、エディタ側はファイルの選択と受け渡しだけを行います。品詞ごとの文脈 ID は辞書のビルドが通るかどうかに直結するため、正しい値を知っているエンジンの側へ寄せています。

追加するファイルは `tools/editor-patch/aivisDictFile.ts` で、パッチ適用時に `src/domain/` へコピーされます。

**12. フレーズ分割辞書の画面**（`tools/patch-editor.mjs`）

長い複合語をひと塊のまま渡すとモデルが読みを外すため、どこで区切るかを表記の側で伝える辞書をエンジンが持っています。これまで登録の口は API だけで画面がなく、辞書ファイルを直接開いて書くしかありませんでした。メニュー「設定 → フレーズ分割辞書」へ画面を足し、読み方＆アクセント辞書と同じ形で登録・編集・削除ができるようにします。

辞書そのものの扱いはエンジンが受け持ち（`/word_splits`）、エディタ側は一覧の表示と受け渡しだけを行います。追加するファイルは `tools/editor-patch/WordSplitManageDialog.vue` と `tools/editor-patch/wordSplits.ts` で、パッチ適用時にそれぞれ `src/components/Dialog/` と `src/domain/` へコピーされます。

**13. 表現指定を含む現在の本文を合成へ渡す**（`tools/patch-editor.mjs`）

IRODORI-VOICE への合成要求では、現在の本文からメモ・ルビ設定を反映した文章を毎回渡します。絵文字や句読点だけを変更した場合や、保存済みプロジェクトを開いた場合も、その行の表現指定を使います。エンジンは読みとの一致を確認して行ごとの文章を優先するため、同じ読みの別行と絵文字が混ざりません。読みを手動で変更した場合は、変更後の読みを優先します。

本家の状態へ戻す場合は `node tools/patch-editor.mjs --revert` を実行してください。

#### 起動

```bash
start-voicevox-editor.bat   # エンジンとエディタが一緒に立ち上がる
```

エンジンの起動情報は、このバッチが環境変数 `VITE_DEFAULT_ENGINE_INFOS` で渡します。
エディタは `.env` より環境変数を優先して読むため、環境ごとに違う Python のパスを
`.env` へ書き残さずに済みます。バッチを通さずに `pnpm run electron:serve` を直接
叩いた場合は `.env` の値（`executionEnabled: false`）が効くため、エンジンは
`start-engine.bat` で別途起動してください。

#### 貼り付けたテキストの分割

**テキスト自動分割は既定の「句点と改行」のままで構いません。** 貼り付けたテキストは `。` の後ろで行へ割られますが、鉤括弧（`「」`・`『』`）の中の `。` では割りません。

この改変を入れる前は、`「ホチキス留め：必ず1枚目の向き・上下を目視確認。左上斜め留め」。` を貼ると `左上斜め留め」。` が独立した行になっていました。鉤括弧の途中で切れた断片であるため、この行だけを合成すると 6kHz 以上のエネルギーが 0.26%（1 行のままなら 10.12%）まで落ち、こもった音になります。

崩れる原因は短さそのものではなく、**文の途中で切れていること**です。完結した一文であれば 17 文字でも 5.54% を保ちます。括弧を使わない地の文は `。` が文の切れ目であるため、そこで割られても音は崩れません。

括弧の外でも行を割りたくない場合は、設定 → テキスト自動分割 を「改行」にしてください。長い行はエンジンが内部で区間へ割ってから合成し、1 本の音声として返すため、割らずに渡しても問題ありません。

#### 導入時に出ることがあるエラー

`pnpm install` の最後で、開発用スペルチェッカー（typos）の展開が失敗することがあります。
VOICEVOX 側のスクリプトが展開先パスをクォートしていないため、**フォルダのパスに空白が
含まれると** 7-Zip のコマンドラインが途中で切れます。エディタの起動には影響しないため、
そのまま進めて構いません。避けたい場合は空白を含まないパスへ配置してください。

### 3. 起動する

```bash
start-voicevox-editor.bat
```

これ 1 つで、エンジンとエディタの両方が立ち上がります。エンジンはエディタが子プロセスとして起動するため、別のウィンドウは増えません。エディタを閉じるとエンジンも一緒に終了します。エディタのメニューから **エンジン → 再起動** も使えます。

バッチは、エンジンの起動方法を次の順で探して、絶対パスでエディタへ渡します。

1. `runtime\Scripts\python.exe`（同梱ランタイムを置いた場合）
2. `..\Irodori-TTS\.venv\Scripts\python.exe`（隣の Irodori-TTS の仮想環境）
3. PATH の `python`
4. `engine\dist\irodori-voice-engine\irodori-voice-engine.exe`（`build-engine.bat` で固めたもの）

Python が見つかった場合は `engine/run_engine.py` をそのまま実行します。エンジンのコードを直したら、エディタを起動し直すだけで反映されます（実行ファイルを作り直す必要はありません）。

`start-engine.bat` は、エンジンだけを動かしたいとき——外部ツールから使う、既存の VOICEVOX へエンジンとして追加する、エンジンの挙動だけを調べる——のために残しています。**エディタと同時に使わないでください。** ポート 50121 が塞がっていると、エディタはもう 1 つのエンジンを別のポートへ起動します。

### 4. 音声モデルを追加する（管理画面）

エディタのメニューから **エンジン → 音声モデルの管理** を選ぶと、エディタ内の画面として開きます（`setup-voicevox-editor.bat` がこの項目を追加します）。ブラウザで直接開く場合の URL は `http://127.0.0.1:50121/admin` です。

VOICEVOX エディタには音声モデルや話者を管理する画面が無いため、そこだけをこの画面が担います。読み上げの操作はこれまでどおりエディタで行ってください。

画面はビルドしたものをエンジンが配信します。`admin/dist` が無い場合は配信されないため、その場合は `cd admin && pnpm install && pnpm build` を実行してください。

**音声モデルの追加**（「音声モデル」タブ）

1 ファイルにまとまったものは、画面のどこへ落としても取り込めます。ばらばらのファイルは、右上の「モデルを追加」から進んでください。

| 形式 | 手順 | 備考 |
| --- | --- | --- |
| `.irvm` | 画面へドロップする | このソフトで作る形式です。4 点セットが 1 つにまとまっています |
| Style-Bert-VITS2 の 3 点セット | 「モデルを追加」→「フォルダを送る」 | `*.safetensors` / `config.json` / `style_vectors.npy` が揃っている必要があります |
| 手元のフォルダ（送らずに取り込む） | 「モデルを追加」→「フォルダを指す」 | パスを渡すとエンジンが直接読みます。重みが大きいときはこちらが速く終わります |

`.safetensors` 単体では取り込めません。重みだけでは話者名もスタイルの定義も分からないためです。学習時の `model_assets/<キャラ名>/` フォルダをそのまま指定してください。「フォルダを送る」では、選んだフォルダの名前が話者の呼び名の初期値に入ります。

**話者の作成**（「話者」タブ）

作り方は 2 つあります。「声を借りる」は取り込んだ音声モデルの声を手本にする方法、「シードから」は音声モデルを使わずに数字だけで声を決める方法です。

**声を借りる** — 取り込んだ音声モデルを選んで名前を付けると、その声を手本にした Irodori-TTS の話者ができます。内部では参照用の音声を数本合成し、それを声の見本として登録しています。作成には十数秒かかります。

声の同一性はモデル側から、抑揚と間の取り方は Irodori-TTS から受け継ぎます。「喜怒哀楽のスタイルも作る」を有効にしておくと、24 種類のスタイルが一緒に作られます（あかるい・よろこび・やさしさ・あんど・じしん・からかい・かんがえ・かんたん・おどろき・てれ・ふあん・あせり・くるしげ・おこり・あきれ・ねむそう・よい・ちからづよく・おねがい・ろうどく・かなしみ・まじめ・ゆっくり・はやくち）。それぞれに注釈絵文字が紐づいており、スタイルを選ぶだけで表現が変わります（[表現の指定](#表現の指定句読点と注釈絵文字)を参照）。顔ぶれは実際に聴いて選んでおり、モデルが破綻しやすい表現（こらえ笑い、ひそひそ声、あくび、泣き声）は外してあります。同梱話者は性格づけのために 3〜4 種へ絞っていますが、写した声はどの役にも回せるよう全種を用意します。なお、この喋り分けは標準チェックポイントでのみ機能します（「エンジン」タブで確認できます）。

「表現の指示」はテンプレから選びます。既定は「指定しない」で、選ばなければ従来どおり素の声になります。指示が入るのはノーマルのスタイルだけで、喜怒哀楽のスタイルはそれぞれ固有の指示を持っているため変わりません。

並ぶのは話し方の指示だけです（丁寧・くだけた・朗読調・まじめ・落ち着き・明るい・余裕・近い距離・呼びかけ・ゆっくり・はやくの 11 種）。声の主を決めるのは参照した音声なので、ここで性別や年齢を指定すると参照側と競合します。選べるのはこの一覧だけで、自由入力の欄はありません。効くことを実測で確かめた言い回しだけを並べています。

**シードから** — 音声モデルを 1 つも持っていなくても話者を作れます。`0`〜`2147483647` の整数と名前を決めると、その値から声が決まります。「引き直す」で別の値を引き、「この声を試す」で聴いてから保存してください。

保存するときは、試聴で読ませた文をもう一度合成し、その音を参照音声として焼き付けます。そのため作成には十数秒かかり、聴いた音がそのまま話者の声になります。焼き付けずに保存すると、シードが同じでも読み上げる文の長さで声が変わります（[声の固定について](#声の固定について)）。スタイルは「ノーマル」1 つだけで、喜怒哀楽のスタイルは付きません。

保存後の読み上げには、表現を優先した設定（40回生成・表現CFG 5・参照CFG 2）を使います。試聴と参照音声の焼き付けには従来どおりエンジンの生成回数を使います。「声を借りる」の設定は変わりません。既存話者の設定は自動では変更しません。

話者スタイルの `num_steps` に生成回数を保存できます。優先順位は、合成APIの `steps`、スタイルの `num_steps`、エンジン設定の順です。未指定のスタイルはエンジン設定に従います。MeanFlow版では表現CFG・参照CFGによる調整が適用されないため、この比較と同じ表現は期待できません。

「表現の指示」はテンプレから選びます。焼き付ける声にも反映されるため、話し方だけでなく声そのものもここで変わります。「声の土台」（落ち着いた女性・明るい若い女性・落ち着いた男性・くだけた男性・中性的なナレーター）と「話し方」の2 群から選べます。声の土台の文面は同梱話者のノーマルと同じものです。既定は「指定しない」で、その場合は焼き付ける声をシード値だけが決めます。

**モデルを作成する**（「モデルを作成」タブ）

ばらばらに配布された次の 4 点を、1 つの `.irvm` へまとめます。フォルダを選べば拡張子から自動で振り分けます。

| 材料 | ファイル | 要否 |
| --- | --- | --- |
| 学習済みモデル | `*.safetensors` | 学習済みか ONNX のどちらか一方は必須 |
| ONNX モデル | `*.onnx` | 同上 |
| ハイパーパラメータ | `config.json` | 必須 |
| スタイルベクトル | `style_vectors.npy` | 必須 |

「作ったあと、そのまま取り込む」を入れておくと、作成と同時に話者一覧へ並びます。切っておくとファイルを受け取るだけになるので、配布用に作る場合はこちらです。

配布用のファイルが要らない場合は、「音声モデル」タブの「モデルを追加」→「フォルダを指す」の方が速く終わります。ファイルを送らずにエンジンが直接読むためです（`.irvm` は作られません）。

ここで付けた名前は、モデル名と話者名の両方になります。`config.json` には学習時のデータセット名（例: `TSUMUGI_JP`）が残っていることが多く、それをそのまま話者名にすると、「音声モデル」一覧と「話者」一覧で名前が食い違って探せなくなるためです。1 つのモデルに複数の話者が入っている場合だけは、どれがどれか分かるように `config.json` 側の名前を使います。

なお `.irvm` に ONNX と Safetensors の両方を入れた場合、合成には Safetensors 側を使います。ONNX は現在のところ推論に使いません。

### 5. 既存の VOICEVOX へ追加する場合

エディタを別に用意せず、既に入っている VOICEVOX へエンジンとして追加することもできます。VOICEVOX の設定からマルチエンジン機能を有効にし、エンジンの接続先として `http://127.0.0.1:50121` を登録してください。本家エンジン（既定 50021）と同時に使えます。

## VOICEVOX ENGINE 互換 API の対応範囲

| 項目 | 対応 | 備考 |
| --- | --- | --- |
| 話者・スタイルの一覧 | ○ | 話者 ID は内部 ID から決定的に生成するため、話者を追加しても既存の ID は変わりません |
| アクセント句の生成 | ○ | 本家と同じく OpenJTalk で解析します |
| ユーザー辞書 | ○ | 登録・編集・削除・インポート。OpenJTalk の解析へ実際に反映します。`/user_dict/aivis` では AivisSpeech と同じ形のファイルを読み書きできます |
| 話速 `speedScale` | ○ | |
| 音量 `volumeScale` | ○ | |
| 前後の無音 `prePhonemeLength` / `postPhonemeLength` | ○ | |
| 読みが取れない行（記号だけの行・空行） | ○ | 前後の無音ぶんの wav を返します。本家と同じ扱いです |
| 出力 `outputSamplingRate` / `outputStereo` | ○ | 既定は VOICEVOX と同じ 24000Hz |
| 複数音声の結合 `connect_waves` | ○ | |
| まとめて合成 `multi_synthesis` | ○ | zip で返します |
| 話者のアイコン・立ち絵 | ○ | 管理画面で付けた画像を返します。付いていない話者は、モデル同梱の画像、それも無ければ識別色から生成した図形になります |
| 更新情報 `update_infos.json` | ○ | エンジンが空の一覧を返します（外部へ問い合わせません） |
| 音高 `pitchScale` / 抑揚 `intonationScale` | △ | 対応する話者でのみ有効です |
| モーラごとの音高・長さの編集 | × | Irodori-TTS はテキストから直接音声を生成するため、モーラ単位の制御機構を持ちません |
| モーフィング合成・歌唱合成 | × | 歌唱用の話者を返さないため、エディタのソング切り替えは表示されません |
| AquesTalk 風記法 | × | |

対応していない機能は `engine_manifest` の `supported_features` で false を返すため、**VOICEVOX エディタ側が該当するコントロールを自動で無効化します**。アクセント欄は表示されますが編集は効きません。

現在の対応状況は `http://127.0.0.1:50121/compat_status` で確認できます。

## 表現の指定（句読点と注釈絵文字）

### 句読点と記号

句読点や記号も、絵文字と同じく長さの予測へ入ります。飾りではなく指示として働くため、書き方で読み方が変わります。実測（同梱話者「やわらか」・同一シード）は次のとおりです。

| 書き方 | 長さの変化 | 語尾（末尾 − 前半の F0） | 効き方 |
| --- | --- | --- | --- |
| 記号なし | 基準 | — | — |
| `。` | +1.00 秒 | ほぼ平ら | 文末を締めます |
| `、` | +0.36 秒 | ほぼ平ら | 間が入ります |
| `？` | +1.44 秒 | **+64.6Hz（上がる）** | ゆっくり問いかけます |
| `！` | −1.04 秒 | **+69.3Hz（上がる）** | 短く言い切り、声も張ります |
| `…` | +0.40 秒 | ほぼ平ら | 余韻が残ります |
| `ー` | +0.72 秒 | ほぼ平ら | 伸ばします |

同じ疑問文でも、`明日は晴れますか？` は語尾が +64.6Hz 上がり、`明日は晴れますか。` は ±0（平ら）になります。文字どおり読み分けています。

**気をつける点が 3 つあります。**

`！` を重ねたときの差は、数値でははっきりしません。5 つのシードで平均を取ると、音量は 1 つで 0.126、2 つで 0.127、3 つで 0.132 と増える向きに揃いますが、差そのものは小さく、F0 の違いは揺らぎ（標準偏差 ±20〜36Hz）に埋もれます。長さは個数によらず一定でした（記号なしから約 0.68 秒短くなる）。強めたいときは重ねるより、`😆` や `💪` の注釈を添えるほうが確実に効きます。

**三点リーダは `…`（U+2026）を使ってください。** 見た目の似た `⋯`（U+22EF）は別の文字で、長さの伸びが +0.40 秒に対し +0.08 秒しかありません。`‥`（U+2025）と `...`（半角ピリオド 3 つ）は `…` へ自動変換されるので、そのままで大丈夫です。`～`（U+FF5E）は `ー` へ変換され、長音として扱われます。全角の `！？` は半角へ変換されますが、どちらの形でも同じように数えられます。

**感嘆詞だけを並べた行は声が薄くなります。** `あっ、あん、ッ、あ～…っ！` のように意味のある語を含まない行は、モデルが息声として読み上げます。声の土台になる 1kHz 未満のエネルギーが普通の文の約 0.3 倍まで落ち、1〜4kHz だけが残るため、AM ラジオのように薄く聞こえます（話者ミライで、普通の文 34.2% に対し 10.8%）。この落ち込みは話者によらず、サンプリング回数を増やしても戻りません（やわらかで 8 回 17.1% → 32 回 14.8%）。エンジンが合成後に低域を補正しますが、`あっ、あんっ、だめぇ、そんなにされたら、こえ、でちゃうから、まってぇ…っ` のように意味のある語を挟むと、補正なしでも 2 倍近く戻ります。文として書くのがもっとも効きます。

### 注釈絵文字

Irodori-TTS は、読み上げ文に混ぜた絵文字を「表現の指示」として解釈します。絵文字だけでは変化が弱い場合があるため、IRODORI-VOICE は下表の注釈に対応する補助キャプションも自動で加えます。

本文に書いた対応絵文字・句読点は、各行の指定を保ったままモデルへ渡します。漢字を含む語は、辞書の指定を適用してからOpenJTalkで解析できた読みへ置き換えます。同じ文章を絵文字だけ変えて複数行に並べても、各行を個別に生成します。本文の途中に注釈絵文字がある場合も、スタイル側の絵文字を追加しません。変化の大きさや自然さは、話者・文章・チェックポイントによって異なります。

たとえば「悲しみに耐えられず、涙を流して嗚咽しながら話している。」は、生成時に「かなしみにたえられず、なみだをながしておえつしながらはなしている。」になります。これは文章を聞き取りやすくするための本文処理です。表示用アクセントの操作とは別で、補助キャプションの文面は変換しません。解析できない語は元の表記を残します。固有名詞や文脈による読み違いは辞書で指定してください。読みを明示することで、従来の漢字入力時とは音声の調子が変わる場合があります。

補助キャプションの自動追加前に行った実測（同じ文・同じシード・同梱話者）では、次の変化がありました。現在の生成結果を保証する値ではありません。

| 絵文字 | 意味 | 長さの変化 | F0 中央値の変化 |
| --- | --- | --- | --- |
| 😱 | 叫ぶ | +0.60 秒 | +41.7Hz |
| 👂 | ささやき・耳元 | +1.08 秒 | +3.5Hz |
| 😪 | 眠そうに | +0.80 秒 | +15.9Hz |


**使い方は 2 通りあります。**

1. **スタイルを選ぶ** — 話者のスタイルに絵文字が紐づいています。エディタでスタイルを切り替えるだけで、対応する絵文字が読み上げ文の先頭へ自動的に付きます。長文が区間へ分割される場合も、すべての区間に付きます。
2. **本文に直接書く** — 「🥺今日はうまくいかなくて……」のように文中へ置くと、その箇所の表現が変わります。スタイルと併用できます。

モデルが解釈できる絵文字は `engine/irodori_voice/vendor/irodori_tts/duration.py` の `ALLOWED_ANNOTATION_EMOJIS` に定義されている 56 種です。一覧にない絵文字は注釈として扱われず、読み上げ対象の文字として音に混ざるため、スタイルへ設定しようとした場合はエンジンが 422 で拒否します。

主なものを挙げます。

| 分類 | 絵文字 |
| --- | --- |
| 感情 | 😊 明るく／😆 楽しく／😭 泣く／😠 怒り／🙄 呆れ／😌 安堵／😟 心配／😲 驚き／😖 苦痛／🥺 震える声 |
| 話し方 | 👂 ささやき／📣 呼びかけ／😱 叫ぶ／🤐 くぐもった／🫣 恥ずかしそうに／😏 からかう |
| 状態 | 😪 眠そうに／😴 眠り／🥱 あくび／🥴 酔って／😰 慌てて／🤔 疑問 |
| 音・効果 | 🤭 くすくす笑い／😮‍💨 ため息／📞 電話越し／📢 エコー／🎵 鼻歌／🥤 飲み込む音／🤧 咳・くしゃみ／💋 リップノイズ |

同梱話者は性格に合う 3〜4 種を、写した声（クローン話者）は 25 種すべてを持ちます。

**補助指示の適用ルール**

- 対応する注釈絵文字を含む文は、合成用の本文だけに末尾の `..` を自動で補います。画面・保存済みの文章には表示されません。句点・感嘆符・疑問符・閉じ括弧がある場合はその直前へ入れます。末尾にすでに `..` や `…` がある文には重ねません。複数文や改行で区切られた文章では、注釈のある文だけが対象です。モデル側では `..` が `…` に正規化され、固定秒数の無音ではなく表現の手がかりとして扱われます。

- 上表の注釈は、文頭・文中・文末のいずれでも自動補助の対象になります。スタイルから付く絵文字も対象です。
- 泣く指定には「悲しみに耐えられず、涙を流して嗚咽しながら話している。」、震える声には「不安で心細く、声を震わせながら恐る恐る話している。」を加えます。morioki で確認した比較サンプルと同じ指示文です。
- 話者の既存キャプションを残して補助指示を加えます。複数の絵文字は出現順にまとめ、同じ絵文字の繰り返しで補助指示は重複しません。読み上げ本文の絵文字自体はそのまま残します。既存キャプションや別の絵文字と矛盾する指示は解釈が不安定になるため、比較時はノーマルで1種類ずつお試しください。
- APIで `caption` を明示した場合は、その指定を優先して自動補助を行いません。空文字列ならキャプションなし、未指定または `null` なら自動補助を使います。
- 長文が分割される場合は、それぞれの生成区間内の絵文字から補助指示を作ります。手書きの注釈を別の区間へ自動では引き継ぎません。
- 生成回数は合成APIの明示指定、話者スタイル、エンジン設定の順に使います。新しく固定したシード話者は表現優先の40回生成、それ以外のスタイル未指定時はエンジンの既定8回です。スタイル強度を0にした場合やMeanFlow版では、キャプションによる補助を期待できません。
- 音や効果もモデルへの生成指示です。電話用フィルターやエコーの後処理、秒数を固定した無音挿入は行いません。表現の強さ・自然さや非言語音の再現性は、実際に生成してご確認ください。

### 表現の指示（キャプション）

話者に設定する「表現の指示」は、読み上げ文とは別系統の条件としてモデルへ渡ります。効き方は話者の作り方で大きく変わります。

実測（同じ話者・同じ文・同じシードで、指示だけを差し替え）:

| 話者の種類 | 指示 | 長さの変化 | F0 中央値の変化 |
| --- | --- | --- | --- |
| 参照あり（声を借りる） | ゆっくり | −0.08 秒 | −9.2Hz |
| 参照あり（声を借りる） | はやくち | −0.12 秒 | −5.6Hz |
| 参照なし（シードから） | ゆっくり | −0.32 秒 | **+62.3Hz** |
| 参照なし（シードから） | はやくち | **−0.88 秒** | +20.9Hz |

参照音声を持つ話者では、声の主を決めているのは参照側です。キャプションも音を変えてはいます（時間の伸縮を揃えたうえでの MFCC 距離が 17〜22）が、長さや声の高さといった全体の傾向はほとんど動きません。参照を持たない話者ではキャプションが声そのものを決めるため、効き方が桁違いになります。

なお「ごく近い距離でささやくように話している。」は、参照ありの話者で音がまったく動きませんでした（MFCC 距離 7.7、長さは完全に同一）。参照音声の声量に押し負けるためと見ています。ささやき声は注釈絵文字 👂 を持つスタイル側が確実なので、テンプレの一覧からは外してあります。

**方言の指示はできません。** 「関西なまりで話している。」のような指示はテンプレから外してあります。方言の実体はアクセント核の位置と語彙ですが、Irodori-TTS は音素列ではなく書かれたテキストをそのまま条件として受け取るため、キャプション側からアクセントへ手が届きません。参照音声を持つ話者では抑揚の骨格を参照側が決めるため、なおさら動きません。方言で読ませたい場合は、読み上げ文そのものを方言で書いてください（「そうなんですよ」ではなく「そうやねん」と書く）。書いた文はそのままモデルへ渡ります。

**一覧に無い絵文字があります。** 😳（動揺）や 😨（恐れ）のように一般的な感情でも、モデルが学習していない記号は注釈として扱われません。スタイルへ設定しようとするとエンジンが 422 で拒否します。本文へ直接書いた場合は読み上げ対象の文字として音に混ざるため、意図しない音になります。

**絵文字と本文の間に空白を入れても問題ありません。** `😌🫶 こんにちは` のような書き方は自然ですが、この半角空白は上流の正規化では落ちず、読み上げ対象の文字としてモデルへ届いて声がこもります。実測では空白の有無だけでスペクトル重心が 2076Hz と 3264Hz に分かれました。エンジンが注釈絵文字の直後の空白を落とすため、書き手は気にせず書けます（英文中の空白は残すので、`Hello World` のような読みは壊れません）。

**本文に注釈絵文字を書いた場合、スタイル側の絵文字は付きません。** 書き手が明示した指示のほうが意図が細かいため、そちらを優先します。`😊😌🫶` のように重なって過剰になることはありません。

**表現によっては音が濁ります。** こらえ笑い（🤭）、ひそひそ声（🤫）、あくび（🥱）、泣き声（😭）は、実際に聴いて破綻が目立ったため、同梱のスタイルからは外しています。本文へ直接書く場合は結果を確認してからお使いください。

## 速度について

合成時間はサンプリング回数と入力の長さで決まります。CPU 実行時の実測値です。

### チェックポイント別（話者「やわらか」）

| 入力 | 標準 40 回 | 標準 8 回（既定） | MeanFlow（4 回） |
| --- | --- | --- | --- |
| 22 文字 | — | 4.7 秒 | **3.2 秒**（0.75x） |
| 38 文字 | — | 7.6 秒 | **5.0 秒**（0.58x） |
| 79 文字 | 25.7 秒 | 13.1 秒 | **9.4 秒**（0.64x） |

括弧内は実時間比で、1.0 を下回れば音声の長さより短い時間で合成できています。
MeanFlow 版は 4 回生成を前提に蒸留されているため、回数を減らしても品質が落ちません。

### MeanFlow 版への切り替え

```bash
curl -X POST "http://127.0.0.1:50121/api/models/select?checkpoint=Aratako/Irodori-TTS-v4.1-Small-MF"
```

一覧と取得状況は `GET /api/models` で確認できます。切り替え後はエンジンを
再起動してください。初回は 2.9GB のダウンロードが走ります。

### 長文の扱い

入力が 60 文字を超えると、句読点を見て 1 区間 30〜40 文字へ自動で分割し、
同じ声のまま繋ぎ直します。Irodori-TTS は 1 回の合成で最大 30 秒までのため、
分割しない場合は末尾が打ち切られます。

分割の方針は `settings.json` で変更できます。

| 設定 | 既定 | 説明 |
| --- | --- | --- |
| `split_long_text` | `true` | 自動分割の有効・無効 |
| `split_target_chars` | `38` | 1 区間の目標文字数 |
| `split_max_chars` | `60` | この長さを超えたら分割する |

### 声の固定について

シードが保証するのは「同じ文なら同じ音になる」という再現性だけで、「違う文でも同じ声になる」
ことではありません。参照音声を持たない話者は声を固定する条件を 1 つも持たず、読み上げる文の
長さが変われば初期ノイズの長さも変わるため、行ごとに別人の声になります。

実測（シード 990526849・表現の指示なしの話者。全行へ同じシードが渡っていることを確認したうえで）:

| 読み上げた文 | 焼き付け前の F0 中央値 | 焼き付け後 |
| --- | --- | --- |
| 10 文字 | 205.6Hz | 141.6Hz |
| 23 文字 | 133.7Hz | 145.2Hz |
| 37 文字 | 119.1Hz | 124.0Hz |
| 42 文字 | 104.2Hz | 136.8Hz |
| 39 文字 | 109.6Hz | 122.4Hz |
| **中央値の幅** | **101.3Hz** | **22.8Hz** |

文が長いほど低くなり、短い行は女性、長い行は男性のように聞こえます。声質（有声区間の長時間
平均スペクトルの一致度）で見ても、行どうしの最小値は 0.783 でした。焼き付け後は 0.967 まで
上がり、参照音声を持つ話者（0.806〜0.865）より安定します。

そのため「シードから」で作る話者は、作成時に一度だけ合成した波形を参照音声として焼き付けます。
既に作ってある話者は、管理画面の話者一覧に出る「声を固定する」であとから固定できます
（`POST /api/voices/{voice_id}/bake-reference`）。話者 ID は変わらないため、エディタ側の
割り当ても、付けたアイコンもそのまま残ります。

同梱話者は参照音声を持ちませんが、スタイルのキャプションで声を指定しているぶん揺れは小さく
（同じ条件で幅 74.5Hz・一致度の最小 0.851）、参照音声を持つ話者と同程度に収まります。書き換え
られないため、さらに固定したい場合は `POST /api/voices/{voice_id}/duplicate` で複製してから
「声を固定する」を押してください。

独自 API（`/api/synthesis`）でシードを明示した場合はそちらが優先されます。ただし参照音声を
持つ話者では、シードを変えても声そのものは変わりません（揺らぐのは抑揚と間だけです）。

## 開発

エディタから使う場合、エンジンは `start-voicevox-editor.bat` が渡した情報をもとにエディタが起動します。エンジン単体で触りたいときは次のとおりです。

```bash
# エンジンを起動（http://127.0.0.1:50121）
python engine/run_engine.py --port 50121

# API の一覧を見る
# http://127.0.0.1:50121/docs

# 互換層の対応状況を確認
curl http://127.0.0.1:50121/compat_status

# 依存ライブラリの読み込みを順に試し、失敗したものを表示する
python engine/run_engine.py --diagnose
```

表現指定の回帰テストは `python engine/tests/test_expression_text.py` で実行できます。辞書は一時領域へ隔離し、同じ読みの別行、保存と再読み込み、手動の読み編集、全56種類の注釈絵文字と33種類の補助キャプション、明示指定の優先、複合注釈・繰り返し、漢字語の読みと辞書指定の優先を確認します。エディタ側はパッチ適用後に `editor-voicevox` で `pnpm run test:unit --project unit tests/unit/store/irodoriExpression.spec.ts` を実行します。テスト時も `VITE_APP_NAME=irodori-voice-editor` を環境変数に設定してください。

管理画面はビルドしたものをエンジンが配信します。変更したら次を実行してください。

```bash
cd admin
pnpm install
pnpm build     # admin/dist へ出力。エンジンが /admin で配信します
pnpm dev       # 画面だけを直したいときは :5174。/api はエンジンへ中継されます
```

`admin/dist` が無い場合、エンジンは `/admin` を配信しません（画面が無いだけで、合成もエディタからの利用も通常どおり動きます）。実行ファイル版では `build-engine.bat` が `admin/dist` を同梱するため、**先に `pnpm build` を済ませてから**ビルドしてください。

`--diagnose` は実行ファイル版でも同じように使えます（`irodori-voice-engine.exe --diagnose`）。音声が合成できない、アクセント欄が 1 句しか出ないといった場合に、どの依存でつまずいているかをトレースバック付きで表示します。

エンジンの設定は `%APPDATA%/IRODORI-VOICE/settings.json` に保存されます。話者プリセットは同ディレクトリの `voices/`、ユーザー辞書は `dict/`、キャッシュは `%LOCALAPPDATA%/IRODORI-VOICE/cache/` です。

## 実行ファイルを作る

```bash
コンパイル.bat
```

Python 環境もエディタの開発環境も要らない、単体で動く形へまとめます。

起動すると、まず何を作るかを聞きます。

```
  1. 両方つくる … CPU 版と GPU 版を続けて作ります（合計 100 分以上）
  2. CPU 版だけ … GPU が無い環境でも確実に動きます
  3. GPU 版だけ … CUDA 12.6。GTX 750Ti 〜 RTX 40xx で使えます
  4. 入れ替えない … いま入っている PyTorch のまま 1 種類だけ作ります
```

**CPU 版と GPU 版は分けて作る必要があります。** PyTorch は CPU 版と CUDA 版で中身が別物で、実行ファイルへ固めた時点でどちらか一方が焼き込まれ、あとから差し替えられないためです。両方を配れば、利用者は自分の環境に合うほうを選べます。

選んだあとは次の順に進みます。

1. **管理画面をビルド** — `admin/dist` を作ります。エンジンがこれを同梱し、`/admin` で配信します（種類によらず共通なので 1 回だけ）
2. **PyTorch を入れ替え** — 選んだ種類に合わせて CPU 版 / CUDA 版へ差し替えます
3. **エンジンを実行ファイルへ** — PyInstaller で `engine/dist/irodori-voice-engine/` へ固めます
4. **エディタを実行ファイルへ** — 上のエンジンを `vv-engine/` として同梱し、Electron のアプリへまとめます

成果物は種類ごとに分かれます。

```text
release/
├── cpu/                        … GPU が無い環境でも動きます
│   ├── IRODORI VOICE Setup.exe      … 414MB
│   ├── IRODORI VOICE Portable.exe   … 414MB
│   ├── IRODORI-VOICE/               … 1.6GB
│   └── 同梱している PyTorch.txt
└── gpu/                        … CUDA 12.6 対応の GPU で速くなります
    ├── IRODORI-VOICE/               … 5.0GB（フォルダ版のみ）
    └── 同梱している PyTorch.txt
```

**GPU 版はフォルダ版だけです。** CUDA ランタイムを含むため 5.0GB になり、インストーラを作る NSIS が抱えられる上限（32bit 実装のため 2GB 前後）を超えます。実測でも `extractEmbeddedAppPackage` で失敗しました。配る際は zip などにまとめてください。作る前から失敗すると分かっているので、`コンパイル.bat` は GPU 版でフォルダ版だけを作ります。

どれもエンジンを同梱しており、起動すると一緒に立ち上がります。別途 `start-engine.bat` を叩く必要はありません。

| 形式 | 出力 | 向いている場面 |
| --- | --- | --- |
| インストーラ | `IRODORI VOICE Setup.exe` | 自分の PC へ導入して使う場合。設定と話者は `%APPDATA%\IRODORI-VOICE` に入り、アンインストールしても残ります |
| 単一実行ファイル | `IRODORI VOICE Portable.exe` | 1 つのファイルで渡したい場合。起動のたびに中身を展開するため、最初の起動には時間がかかります |
| フォルダ | `IRODORI-VOICE\` | USB メモリや共有フォルダから使う場合。展開の待ち時間がありません |

所要時間は 1 種類あたり 50 分以上、途中でディスクを 20GB ほど使います。両方作る場合は倍かかります。単一実行ファイルの圧縮に時間がかかるためで、フォルダ版だけでよければ `tools/patch-editor.mjs` の「配布ビルドの形式」から `portable` を外すと短くなります。

**GPU 版に CUDA 12.6 を選んでいる理由**は、これが Maxwell から Hopper（GTX 750Ti 〜 RTX 40xx）までを一度に覆う最後の世代だからです。CUDA 12.8 以降のビルドは Maxwell / Pascal / Volta のサポートを削除しており、GTX 10xx 世代が動かなくなります。RTX 50xx（Blackwell）向けが必要になった場合は、`コンパイル.bat` の GPU 版の行を `cu128` へ変えたものを別に作ってください。

エンジンだけを固めたい場合は `build-engine.bat` を使ってください。エディタは含まれません。

なお、本家の Windows 向けターゲットは `nsis-web`（インストーラが本体を分割ダウンロードする形式）ですが、これは配布サーバーを前提としており、付属の `installer.nsh` も 952 行すべてがその前提で書かれているため使っていません。`nsis` の設定は `tools/patch-editor.mjs` で別に置いています。

**その際、`nsis.include` の指定が必須です。** electron-builder は `build/installer.nsh` を自動的に読み込む仕様で、`include` を指定しないかぎり通常の `nsis` ビルドへもこのスクリプトが混入します。すると `nsis-web` でしか定義されない変数（`APP_PACKAGE_STORE_FILE`）を参照して makensis が警告を出し、警告はエラー扱いのためビルドが落ちます。これを避けるため、空のカスタムスクリプト `build/irodori-installer.nsh` を置いて `include` に指定しています。インストーラへ処理を足したい場合はこのファイルに書いてください。

**パスに日本語が含まれる場合の注意もあります。** インストーラを作る makensis は、渡されたパスを ANSI として扱うため、非 ASCII のパスにあるファイルを開けません。このソフトを日本語を含むフォルダ（例: `N:\音声合成\IRODORI-VOICE`）へ置くと、electron-builder が生成したアイコンを読み込めず、インストーラの作成に失敗します。`コンパイル.bat` は出力先をドライブ直下の `irodori-build` へ逃がすことでこれを避けています（環境変数 `IRODORI_BUILD_OUTPUT` で指定し、`directories.output` がこれを読みます）。同じドライブへ置くため、`release` へ移す時間はかかりません。
